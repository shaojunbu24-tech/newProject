# 电力设备多模态标注规则3.0

## 1. 设计目标

3.0解决两个彼此独立的问题：标签候选树既可以作为硬约束，也可以只作为专业参考；同一标注既需要完整审计记录，也需要干净、适合训练和检索的图像内容JSON。

每张图固定产出两个文件：

```text
原始图像
  └── *.audit.json    审计版、权威事实源
        └── *.content.json  内容版、由脚本确定性导出
```

禁止分别人工维护两份JSON。对象、缺陷或证据变化后，必须重新导出内容版。

## 2. 两种标注模式

| 模式代码 | 中文名称 | 标签树作用 | 候选外标签 | 主要用途 |
|---|---|---|---|---|
| `STRICT_PACKAGE` | 严格标签包 | 硬约束 | 只能使用`OTHER_REVIEW`，不得进入受控标签训练 | 稳定分类、正式生产数据、可复现实验 |
| `REFERENCE_PACKAGE` | 参考标签包 | 推荐词表和相似标签参考 | 允许中文开放标签，但必须保存映射状态并人工复核 | 标签发现、开放词汇标注、候选树扩展 |

模式只改变标签约束，不改变对象树结构、证据要求和来源隔离规则。

### 2.1 严格标签包模式

阶段一至三按2.0方式逐步披露候选。每次选择必须位于当前候选代码数组中，并保存轨迹编号、父节点、标签包版本和候选快照摘要。

对象或缺陷无法匹配时，使用`OTHER_REVIEW`并填写候选外描述。包含`OTHER_REVIEW`的样本可以保留用于树扩展，但不能进入受控标签训练。

### 2.2 参考标签包模式

先观察图像，再用候选树查找同义、近义或上位标签。允许以下三种结果：

1. 精确匹配：使用候选树代码和中文名称；
2. 近似匹配：保留图像对应的开放中文标签，同时记录最近候选；
3. 未匹配：代码留空，保存开放中文标签、视觉定义、最近候选为空及待审核状态。

开放标签必须满足：

- 中文名称描述图像中可见的对象或现象，不能把故障原因当视觉事实；
- `标签来源`为`候选树参考扩展`或`人工确认扩展`；
- `候选树映射.映射状态`为`近似匹配`或`未匹配`；
- 记录最近候选代码、最近候选名称和差异说明；
- 未经人工批准，不得进入受控分类训练；人工批准后可以进入开放词汇数据集或下一版标签树候选池。

参考模式不是自由编造：标签仍需绑定可见对象、载体关系和直接视觉证据。

## 3. 两个输出视图

### 3.1 审计版

使用`标注规则3.0_审计版.json`。它是唯一权威事实源，保存：

- 标注模式和训练策略；
- 候选披露轨迹、候选代码数组、选择代码和快照摘要；
- 标签来源、候选树映射和开放标签复核状态；
- 嵌套标注对象树、缺陷载体和直接证据；
- 确定性规则校验、大模型语义复核、最终门禁和人工审核。

### 3.2 内容版

使用`标注规则3.0_内容版.json`作为输出契约。内容版只保存：

- 图像基本信息和有来源的外部信息；
- 图像路由结果；
- 主要对象主题；
- `设施 → 设备 → 部件 → 子部件 → 缺陷`嵌套对象树；
- 环境、关联关系、视觉证据和不确定信息；
- 多模态描述和组合图像检索标注。

内容版删除候选披露轨迹、候选代码数组、快照摘要、候选树路径、标签来源、候选树映射、规则校验详情和人工审核过程。保留对象编号、缺陷编号和已经选择的稳定标签代码，因为它们用于对象引用和训练映射。参考模式的开放标签没有稳定代码时，代码字段省略，仅保留中文名称。

运行以下命令导出：

```bash
python3 scripts/export_content_view.py input.audit.json --output output.content.json
```

## 4. 共同标注流程

```text
图像与文件名
  ↓
选择STRICT_PACKAGE或REFERENCE_PACKAGE
  ↓
图像路由
  ↓
建立嵌套对象树
  ↓
按实际载体标注缺陷和直接证据
  ↓
模式感知的确定性校验
  ↓
大模型语义复核和人工门禁
  ↓
导出内容版JSON
```

文件名、设备台账和工单属于外部信息。电压、线路名、杆号、故障原因和严重等级必须记录来源，不能冒充图像直接可见事实。

缺陷必须嵌套在实际载体节点内。`雷击`属于原因，`一般/严重`属于业务等级；可见光标签应描述污秽、灼伤、焦斑、闪络路径、破损等可见现象。

## 5. 校验门禁

两个模式共同检查：JSON结构、对象树嵌套、编号唯一、缺陷载体、直接证据、来源隔离、描述一致性和派生输出时效。

严格模式额外检查：

- 正式代码存在于标签树；
- 选择代码位于对应候选快照；
- 对象与父对象、缺陷与载体关系有效；
- `OTHER_REVIEW`不能进入训练。

参考模式额外检查：

- 每个对象和缺陷具有中文名称；
- 候选外名称具有映射状态、最近候选和复核状态；
- 未批准开放标签不能进入受控训练；
- 与候选树同义的标签优先归一，不重复制造新词。

执行：

```bash
python3 scripts/validate_annotation.py input.audit.json
python3 scripts/self_test.py
```

## 6. 数据使用建议

- 受控分类、检测和严格检索实验：优先使用严格模式且最终门禁通过的内容版；
- 开放词汇识别、标签发现和知识扩展：使用参考模式审计版进行专家归并，再导出内容版；
- 训练数据只读取内容版，质量分析和问题追溯读取审计版；
- 数据划分仍按线路、杆塔、设备或巡检事件分组，避免同事件泄漏到不同集合。
