# 电力图像标注1.2

## 版本边界

使用1.2作为回溯稳定版。它保留四阶段结果结构，但不强制把路由、对象和缺陷拆成多次模型调用，也不要求记录逐层候选快照。需要严格渐进披露、双阶段门禁或输电绝缘子专项时，改用`power-image-annotation` 2.0。

所有正式代码必须来自`references/标签候选树1.2.json`。不得从2.0候选树补标签；候选缺失时使用`OTHER_REVIEW`并退出训练集，或先单独扩展1.2台账版本。

## 标注流程

1. 复制`assets/标注规则1.2.json`作为每图一份的结果骨架。
2. 完整读取`references/标注规则1.2.md`，再读取`references/标签候选树1.2.json`。一次模型调用可以同时使用与当前图像有关的路由、对象和缺陷候选。
3. 先观察图像，再解析文件名。把电压等级、站线名称、杆号、缺陷原词和严重度写入`外部信息`并注明来源；不得把文件名直接当视觉结论。
4. 按`设施 → 设备 → 部件 → 子部件 → 缺陷`写入嵌套`标注对象树`。不要建立并列的顶层设备、部件或缺陷数组。
5. 缺陷必须嵌套在实际载体中，并至少绑定一条`视觉证据`。原因、严重等级和不可见属性分别写入外部信息或不确定信息。
6. 从审核后的对象树派生`多模态描述`和`组合图像检索标注`，写回同一JSON。
7. 运行确定性校验：

```bash
python3 scripts/validate_annotation.py /absolute/path/to/annotation.json
```

校验失败时修改权威JSON后重跑。不得为了通过校验而自动创造代码或虚构不可见父设备。

## 一次调用提示组织

向模型一次提供以下内容即可：图像、文件名、1.2模板、当前任务涉及的候选树内容，以及下列约束：

```text
先完成路由，再建立嵌套对象树，最后把缺陷绑定到载体。
正式代码只能从给定1.2候选树选择。
图像事实与文件名信息分开。
每个缺陷必须给出可见证据；证据不足则标不可判定或待复核。
派生描述只能使用结构化标注中已经审核的事实。
```

这里的“一次调用”只合并阶段一至三的初标，不取消逻辑顺序和确定性校验。
