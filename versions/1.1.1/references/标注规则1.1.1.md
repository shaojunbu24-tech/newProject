# 电力设备多模态标注规则1.1.1

## 1. 版本定位

1.1.1是1.0的树形结构升级版。它保留1.0的图像信息、业务场景、视觉证据、多模态描述和组合检索字段，只对对象表达方式和实例完整性做重点升级。

权威结构为：

```text
设施
├─ 设备
│  ├─ 部件
│  │  ├─ 子部件
│  │  └─ 缺陷
│  └─ 缺陷（仅当缺陷载体确为整体设备）
├─ 部件（线路元件可直接属于杆塔设施）
│  └─ 缺陷
└─ 缺陷（仅当缺陷载体是设施整体）
```

不再允许顶层并列的`设备实例`、`部件实例`和`缺陷实例`。`所属设备编号`和`缺陷所在对象编号`不再是主要归属方式，归属关系由JSON嵌套位置直接表达。

## 2. 为什么杆塔下允许直接出现部件

变压器、柱上开关等是设备，它们的套管、箱盖和操作机构应嵌套在`设备实例`内。但杆体、横担、导线、线路绝缘子和金具是杆塔或架空线路的组成元件，不应为了套用字段而虚构一个设备。因此：

- 杆上变压器：`杆上台区设施 → 配电变压器设备 → 箱盖/套管/散热片 → 缺陷`。
- 线路绝缘子：`杆塔设施 → 绝缘子部件 → 缺陷`。
- 柱上开关支撑绝缘子：`杆塔设施 → 柱上开关设备 → 支撑绝缘子部件 → 缺陷`。

## 3. 可分辨实例穷举规则

本版的核心新规则是“一个可分辨实例，一个对象编号，一个边界框”。

1. 同图可见3只绝缘子时，必须建立`部件01`、`部件02`、`部件03`，不得只建立一个“多只绝缘子”大框。
2. 同一设备上可见7只套管时，应标注7个套管实例；不得用“套管组×7”取代。
3. 绝缘子串作为运行上的整体时，一串对应一个实例；串内瓷盘仅在需要盘片级缺陷时继续嵌套为子部件。
4. 仅当小目标严重遮挡、重叠或分辨率不足时，才可不逐个标注；必须在`未标注对象及原因`中记录类别、估计数量和原因。
5. 不标注背景车辆、建筑、树木等非电力对象，但可写入环境描述。
6. 标注覆盖率的主要范围是：主设施、主设备、缺陷载体，以及与缺陷载体同类的所有可分辨实例。

## 4. 边界框与状态

- 边界框均使用`[x_min, y_min, x_max, y_max]`的0~1000归一化坐标。
- 对象框覆盖完整可见部分，不强行包含被遮挡区域。
- 每个对象单独记录`状态`、`可见程度`和`识别置信度`。
- 同类对象中只有一个存在异常时，只把缺陷嵌套在该实例内，其余实例将`缺陷实例`保持为空数组。

## 5. 缺陷和文件名信息分离

文件名中的电压等级、线路名、杆号、缺陷原词和严重等级写入`外部信息.文件名解析`，并记录来源。图像中只看到黑色表面痕迹时，可标“放电样痕迹”，但不得仅根据文件名确认“雷击”或“灼烧”原因。

每个缺陷必须：

- 嵌套在真实载体中；
- 有独立`缺陷编号`和边界框；
- 至少对应一条非空`视觉证据`；
- 图像不可判定的原因、严重等级和运行影响写入`不确定信息`。

## 6. 校验

执行：

```bash
python3 校验1.1.1标注.py 例子/某张图像.json
python3 校验1.1.1标注.py --all
```

校验器检查：版本、顶层并列数组、嵌套类型、对象/缺陷编号唯一性、边界框、缺陷证据、绝缘子逐实例标注和覆盖统计一致性。
