# 电力图像标注1.1.1

## 版本边界

1.1.1保留1.0的图像信息、业务场景、视觉证据、多模态描述和组合检索字段，只在对象表达方式和实例完整性上做重点升级：把设施、设备、部件、缺陷改成嵌套对象树，并要求可分辨实例逐个标注。它不依赖候选标签树，也不要求逐层候选披露快照；需要严格渐进披露、双阶段门禁或输电绝缘子专项时，改用`power-image-annotation` 2.0；需要一次加载标签包的回溯稳定版时，参考`power-image-annotation-v1-2`。

## 权威对象树结构

```text
设施
├─ 设备
│  ├─ 部件
│  │  ├─ 子部件
│  │  └─ 缺陷
│  └─ 缺陷（仅当缺陷载体确为整体设备）
├─ 部件（线路元件可直接属于杆塔设施）
│  └─ 缺陷
└─ 缺陷（仅当缺陷载体是设施整体）
```

不再允许顶层并列的`设备实例`、`部件实例`和`缺陷实例`。归属关系由JSON嵌套位置直接表达，不能只靠`所属设备编号`或`缺陷所在对象编号`。

## 标注流程

1. 为每幅图像复制`assets/标注规则1.1.1.json`作为结果骨架。
2. 完整读取`references/标注规则1.1.1.md`再开始；不要凭记忆改写字段。
3. 先观察图像，再解析文件名。把电压等级、线路名、杆号、缺陷原词和严重等级写入`外部信息.文件名解析`并记录来源；文件名信息不得直接替代视觉结论。图像中只看到黑色表面痕迹时可标“放电样痕迹”，但不得仅根据文件名确认“雷击”或“灼烧”原因。
4. 按`设施 → 设备 → 部件 → 子部件 → 缺陷`建立嵌套对象树。杆上变压器按“杆上台区设施→配电变压器设备→箱盖/套管/散热片→缺陷”；线路绝缘子按“杆塔设施→绝缘子部件→缺陷”；柱上开关支撑绝缘子按“杆塔设施→柱上开关设备→支撑绝缘子部件→缺陷”。
5. 可分辨实例逐个标注：每只可见绝缘子、每只套管分别建立一个对象实例并各自给出边界框，不得用“绝缘子组”“套管组”大框替代。同一串绝缘子作为运行整体时一串对应一个实例；串内盘片仅在需要盘片级缺陷时嵌套子部件。仅当小目标严重遮挡、重叠或分辨率不足时才可不逐个标注，并必须在`实例覆盖统计.未标注对象及原因`记录类别、估计数量和原因。
6. 边界框使用`[x_min, y_min, x_max, y_max]`的0~1000归一化坐标，覆盖完整可见部分。每个对象单独记录`状态`、`可见程度`和`识别置信度`；同类多个实例中只有一个异常时，只把缺陷嵌套在该实例内。
7. 缺陷必须嵌套在真实载体中，有独立`缺陷编号`和边界框，且至少对应一条非空`视觉证据`。图像不可判定的原因、严重等级和运行影响写入`不确定信息`。
8. 从审核后的对象树派生`多模态描述`和`组合图像检索标注`，写回同一JSON。
9. 运行确定性校验：

```bash
python3 scripts/validate_annotation.py /absolute/path/to/annotation.json
python3 scripts/validate_annotation.py --all
```

校验失败时修改权威JSON后重跑；不要为了通过校验而自动创造代码、合并实例或虚构不可见父设备。

## 示例与维护

需要模仿格式时读取`assets/examples/`中的示例。示例用于结构参考，不替代对新图像的视觉判断；示例只打包结构JSON，原始巡检图不随Skill分发，`原始图像路径`仅作追溯。

修改规则或示例后运行`scripts/validate_annotation.py --all`确认全部通过。1.1.1与1.2、2.0、3.0分别维护，不把一方的新代码静默同步到另一方。
