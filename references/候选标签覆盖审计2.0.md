# 候选标签树覆盖审计 2.0

## 1. 审计范围

本次审计对照以下内容：

1. 《配电架空线路目标识别人工智能落地应用方法与实践》中的杆塔、杆上设备、杆塔元件、运行环境、拍摄位置和缺陷批次；
2. 当前`data/images`及`data/images/images2`目录中的64张项目图片；
3. `绝缘子/本体/釉表面灼伤`批次138张图片已知的目录语义和文件名词汇；
4. 2.0目录中的5组存量嵌套示例和2组绝缘子严格结构示例；
5. 阶段一至三渐进式披露需要的路由、设备主题、载体缺陷和候选快照数据；
6. 阶段四“确定性规则校验＋大模型语义复核＋最终门禁”需要的配置与结果模板。

本审计验证候选台账能否支持当前项目试标和Skill运行，不替代配电、变电等领域专家对标签定义的最终审定。

122项不能解释为“PDF官方100个缺陷实标签已经一一复原”。该数字同时包含配电架空线路、绝缘子专项、当前变电站样本所需异常，以及`NO_VISIBLE_ANOMALY`等历史兼容控制代码。`NO_VISIBLE_ANOMALY`在新标注中只表达检查结论，不建立正式缺陷实例，也不参与缺陷训练。

PDF中的缺陷标签按多个年度批次发布，并混有虚标签、辅助标签和非缺陷状态；正式生产前仍应取得官方电子标签台账，逐条核对编号、定义、虚实属性、启用版本和训练用途。

## 5A. 绝缘子专项覆盖边界

绝缘子专项按对象层级表达为：

```text
配电杆塔或输电杆塔/线路通道
→ 绝缘子串（输电按需）或绝缘子类型
→ 绝缘子本体/瓷本体/玻璃本体/复合本体
→ 釉表面、伞裙或端部金具
→ 可见缺陷
```

已覆盖的核心可见缺陷包括破损、污秽、放电样痕迹、釉表面灼伤、电弧烧伤、闪络路径、电痕或电蚀、玻璃体自爆或缺损、复合伞裙破损、芯棒外露和端部金具异常。目录或文件名中的“雷击”保存为外部故障原因，“一般/严重”保存为外部业务等级；二者都不得直接替代视觉结论。图像证据不足时使用不可判定或人工复核状态，不使用`OTHER_REVIEW`冒充已确认缺陷。

输电架空线路目前只开放上述绝缘子专项。导线、地线、金具、间隔棒、防振锤等仍是规划词表，因此不能宣称输电全专业已覆盖。

## 5. 材质—部件—缺陷边界

本次新增的杆塔部件和约束解决了“杆塔是否可以生锈”的上位概念歧义：

```text
水泥杆/复合材料杆 → 杆体 → 金属腐蚀：禁止
钢管杆/角钢塔 → 杆体或塔身 → 腐蚀：允许
任意材质杆塔 → 金属抱箍 → 抱箍锈蚀：允许
任意材质杆塔 → 金属横担 → 横担锈蚀：允许
钢管杆等 → 法兰或紧固件 → 法兰/螺栓锈蚀：允许
```

因此约束必须联合“父设施静态属性＋实际缺陷载体”执行，不能只根据“杆塔”上位标签一刀切。

当前已对水泥杆、复合材料杆和金属杆塔的腐蚀候选建立基础规则；裂纹、老化、基础缺陷和复合材料专有缺陷仍需要专业人员继续细化定义。

## 7. 两阶段自动校验覆盖

### 确定性规则校验

模板和台账已经固定以下检查顺序：

1. JSON结构；
2. 标签台账；
3. 渐进披露轨迹；
4. 候选树路径；
5. 对象树关系；
6. 载体缺陷兼容；
7. 静态属性约束；
8. 来源和证据形式；
9. 任务完整性。

规则问题支持`阻断、警告、提示、不适用`四级，并要求记录规则编号、对象路径、实际内容、期望要求、处理建议和退回阶段。

### 大模型语义复核

模板已经预留：

- 图像路由合理性；
- 主要对象和对象树合理性；
- 设备部件识别合理性；
- 缺陷与可见证据一致性；
- 明显遗漏检查；
- 文件名和视觉结论来源隔离；
- 派生描述一致性；
- 人工复核原因。

大模型复核不能替代规则引擎，也不能直接写入候选外正式标签。任何修改建议必须退回相应阶段修改权威结构化标注后重新校验。

### 批次校验

数据泄漏和近重复图像检查属于数据集导出阶段，不在单图JSON中伪装为“通过”。应按线路、杆塔、设备和巡检事件进行分组，并保证同一事件不会跨训练、验证和测试集。

## 9. 自动校验执行

执行：

```bash
python3 校验候选树.py
```

当前脚本检查：

- 两个JSON文件的语法和模板关键字段；
- PDF五个基础知识层的标签数量；
- 在用配电架空设备是否全部具有部件组；
- 设施和设备部件映射是否引用有效部件组；
- 对象载体、载体缺陷和部件缺陷映射是否闭合；
- `NO_VISIBLE_ANOMALY`是否被错误放入新缺陷候选；
- 跨字段规则编号、执行层和代码引用；
- 四阶段顺序、候选披露轨迹必填字段和两阶段审核结构；
- 当前64张图片及绝缘子专项138张批次所需代码是否存在；
- 5个存量示例的对象代码、缺陷代码和主要对象引用是否有效；
- 配电、输电绝缘子严格结构示例能否在不使用`--allow-legacy`时达到零阻断、零警告。

脚本通过只说明台账结构和引用闭合，不说明每张图的视觉标注已经正确。

## 10. 下一步生产化要求

1. 从业务单位取得PDF对应的官方机器可读标签台账，核对100类缺陷的最终代码、虚实属性和启停版本；
2. 由配电和变电专业人员分别审核设施—设备—部件—缺陷关系；
3. 继续细化复合材料杆、角钢塔、钢管杆、基础和连接件的材质专用缺陷；
4. 对“渗漏油/油污痕迹”“雷击/放电样痕迹”等视觉标签与业务原因标签继续分开；
5. 在现有输电绝缘子专项之外，继续为输电导地线、金具和通道，以及发电、用电建立独立领域标签包；
6. 通过独立审核样本评估大模型语义复核的漏报率、误报率和与人工审核的一致性；
7. 标签通过专家审核后再把台账状态从“待领域专家终审”改为“已发布”。
