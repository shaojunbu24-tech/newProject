# 电力设备多模态标注规则 2.0

## 1. 目标与适用边界

2.0以结构化JSON作为唯一事实源，支持以下输出：

- 设施、设备、部件、子部件和缺陷识别训练数据；
- 表计、开关位置、油位、温度等状态量训练数据；
- 单图中文描述和多模态提示词；
- 参考图—修改文本—目标图组合检索数据；
- 配电架空线路六层知识标注；
- 输电、变电、配电、发电等领域标签包扩展；
- 确定性规则校验、大模型语义复核、人工审核和标签版本管理。

2.0不允许模型自由创造设施、设备、部件或缺陷标签。所有正式标签必须来自`标签候选树2.0.json`。候选树之外的内容只能暂记为`OTHER_REVIEW/其他待复核`，经专家审批并进入新版本台账后才能参与训练。

当前标签树已经覆盖配电架空线路基础六层知识，以及本项目出现的部分变电站设备和缺陷；不应把“能够完成图像路由”等同于“已经具备完整专业标注能力”。各领域成熟度以候选树和覆盖审计为准。

## 2. 不变的四阶段流程

```text
原始图像与文件名
  ↓
阶段一：图像路由
  业务域 → 设施场景 → 拍摄任务 → 适用标签包
  ↓
阶段二：设备主题分层标注
  设施/线路 → 主设备 → 部件 → 子部件 → 静态属性
  ↓
阶段三：缺陷标注
  根据载体类型加载缺陷候选 → 绑定载体 → 记录可见证据
  ↓
阶段四：自动校验
  规则校验 → 大模型语义复核 → 最终门禁
  ↓
派生输出
  纯视觉描述、业务描述、检索描述、组合检索修改文本
```

四阶段的业务含义和标注对象树结构不变。渐进式披露发生在阶段一至三：模型只能看到当前阶段、当前场景和当前父节点允许的候选，不能一次加载全量标签台账。

## 3. 渐进式披露与阶段门禁

### 3.1 披露原则

1. 阶段一只披露路由候选，不披露设备部件和缺陷；
2. 阶段一路由完成后，阶段二只加载已激活场景的设备主题树；
3. 阶段二在同一场景标签包内按`设施/线路→设备→部件→子部件→静态属性`逐层显示；
4. 阶段二完成并生成待检查载体队列后，阶段三才披露缺陷候选；
5. 阶段三每次只披露当前载体经过业务域、场景、部件、材质、模态和版本过滤后的候选；
6. 最终选择必须属于当时实际披露的候选快照；
7. 未披露标签即使存在于总台账中，也不能被模型直接选择；
8. 阶段四发现问题后退回受影响阶段，受影响阶段之后的审核结果和派生文本全部失效。

### 3.2 候选披露轨迹

每次候选选择必须记录：

```json
{
  "轨迹编号": "轨迹03",
  "阶段代码": "SUBJECT",
  "父节点代码": "DTR_3P",
  "标签包名称": "配电架空线路六层知识",
  "标签包版本": "2.0",
  "候选代码": ["TR_TANK_TOP", "TR_HV_BUSHING", "TR_RADIATOR"],
  "选择代码": ["TR_TANK_TOP"],
  "候选快照摘要": "规范化候选数组的SHA-256摘要",
  "选择结果状态": "已完成"
}
```

完整候选数组用于复现当次选择，摘要用于发现标签台账更新后历史候选被意外替换。候选披露轨迹属于审核元数据，不作为视觉训练特征。

### 3.3 阶段状态

阶段固定代码和顺序为：

```text
ROUTE → SUBJECT → DEFECT → VALIDATE → DERIVE
```

阶段状态只能从以下枚举中选择：

```text
未开始、进行中、已完成、退回修改、待人工复核、不适用
```

`ROUTE`未完成时禁止进入`SUBJECT`；`SUBJECT`未完成时禁止进入`DEFECT`；前三阶段存在`未处理`时禁止进入`VALIDATE`；最终门禁未通过时禁止进入`DERIVE`。

## 4. 业务域与设备类别必须分开

业务域描述设备所处的生产业务场景，设备类别描述图中对象是什么。不能因为对象是变压器，就一律把业务域标成“变电”。

```text
10kV线路杆号 + 杆上配电台区 + 三相变压器
→ 业务域：配电
→ 设施场景：配电架空线路
→ 设备类别：三相配电变压器

500kV变电站 + 2号主变 + 散热器
→ 业务域：变电
→ 设施场景：户外变电站
→ 设备类别：主变压器
```

文件名可以帮助判断业务域、站线名称和设备编号，但必须记录来源；图像无法验证的信息不能伪装成视觉结论。

信息来源优先级为：

```text
人工确认 > 设备台账/工单 > 图像可见证据 > 文件名解析 > 模型推测
```

“模型推测”不得单独生成正式站点、线路、杆号、相位、故障原因和严重等级。

## 5. 阶段一：图像路由

### 5.1 固定顺序

1. 从固定候选中选择业务域；
2. 只显示该业务域允许的设施场景；
3. 选择拍摄任务、拍摄范围和图像模态；
4. 判断图像清晰程度、遮挡程度和可继续标注状态；
5. 根据业务域与设施场景激活阶段二标签包。

### 5.2 路由候选

- 业务域：发电、输电、变电、配电、用电、跨领域、无法判定；
- 拍摄任务：设备识别、缺陷巡视、状态核查、表计读取、铭牌采集、红外测温、通道巡视、其他待复核；
- 拍摄范围：场站全景、线路通道、杆塔全景、杆塔塔顶、杆塔塔头、杆塔塔身、杆塔塔基、设备全景、设备部件近景、缺陷特写、铭牌图、表计图、红外图、非标准图；
- 图像模态：可见光、红外、可见光与红外配对、系统截图、模态不可判定；
- 路由状态：可以、部分可以、需要人工路由、无效图像。

### 5.3 路由输出

阶段一只产生路由事实和激活标签包，不直接建立缺陷：

```json
{
  "业务域": "DIS",
  "设施场景": "DIS_OHL",
  "拍摄任务": "缺陷巡视",
  "拍摄范围": "gantashebei",
  "图像模态": "VISIBLE",
  "激活标签包": ["配电架空线路六层知识"]
}
```

文件名解析结果写入`外部信息.文件名解析`；路由视觉证据写入`图像路由.路由视觉证据`，两者不得混写。

## 6. 阶段二：设备主题分层标注

### 6.1 对象层级与JSON保存方式

```text
业务域
└── 设施场景
    └── 设施或线路实例
        ├── 设备实例
        │   └── 部件实例
        │       └── 子部件实例
        └── 直接属于设施或线路的部件实例
```

权威JSON必须使用嵌套的`标注对象树`保存包含关系，不把设施、设备、部件和缺陷作为互相并列的顶层数组。包含关系由嵌套位置表达；只有邻近、连接和跨对象影响等非包含关系才写入`关联关系`。

每个对象必须保存：

- 对象类型和全树唯一编号；
- 标签代码、中文名称和台账版本；
- 候选树路径；
- 对象角色和可见程度；
- 可用时保存归一化边界框和视觉识别置信度；
- 适用的静态属性；
- 阶段三使用的缺陷检查状态。

### 6.2 逐层候选选择

阶段二加载一个场景设备主题包，在包内逐层披露：

```text
当前场景设施候选
→ 选中设施后披露该设施允许的设备和直接部件
→ 选中设备后披露该设备允许的部件
→ 选中部件后按需要披露子部件和静态属性
```

阶段二不披露缺陷候选。设施部件与设备部件分开维护，例如杆塔是设施，不能为了复用设备字段而虚构成设备实例。

### 6.3 选择规则

- 主要对象：每张有效图至少一个，可以是设施、设备或部件；
- 部件：零到多个，只标达到清晰度和尺寸要求的可见部件；
- 子部件：仅在缺陷定位、检索或业务规则需要时标注；
- 同类多实例：逐实例标注，不能只写数量后省略实例；
- 虚标签：不得直接标注，由实标签自动合并生成；
- 辅助标签：只用于过滤、废弃和非目标等业务逻辑；
- 候选外对象：正式代码只能选`OTHER_REVIEW`，并记录候选外原词；
- 父对象不可见：允许部件直接挂在设施节点，但必须说明“父设备图外未实例化”，不得虚构不可见父设备。

配电线路的绝缘子、导线、金具、横担、拉线和标志牌可以直接属于杆塔或线路设施。变压器套管、散热器和储油柜等设备部件必须嵌套在对应变压器设备实例中。

输电架空线路当前只开放绝缘子专项：`TRA_TOWER/输电杆塔`或`TRA_LINE_CORRIDOR/输电线路通道`可以包含`TRA_INSULATOR_STRING/输电绝缘子串`、具体绝缘子类型或`INSULATOR_GENERIC/绝缘子（类型不可判定）`，再继续披露本体、釉表面、伞裙和端部金具。该专项不使导线、地线、金具、间隔棒等规划名称自动成为正式标签。

### 6.4 静态属性

静态属性同样必须从当前对象候选中选择。例如杆塔可选择：

- 材质：水泥杆、钢管杆、角钢塔、复合材料杆、不可判定；
- 拓扑主功能：直线杆、转角杆、分支杆、耐张杆、终端杆、不可判定；
- 特殊结构用途：门形杆、变压器台架杆、架空线路转入地电缆杆；
- 回路：单回路、双回路、多回路、不可判定；
- 标志牌：杆号牌、警示牌、相序牌、台区铭牌。

静态属性不能仅凭文件名写成视觉结论；不可稳定判断时必须使用“不可判定”。

### 6.5 状态量与缺陷分离

表计读数、开关分合位置、油位和温度写入`状态量标注`。正常读数不能为了填充缺陷字段而标成缺陷；读数无法稳定辨认时保存“属性不可判定”或相应不可辨认状态，并按规则决定是否需要人工复核。

### 6.6 配电架空线路六层知识映射

| 六层任务 | 2.0结果位置 |
|---|---|
| 拍摄位置 | `图像路由.拍摄范围` |
| 杆塔 | 杆塔设施节点及其`属性` |
| 杆上设备 | 杆塔设施节点中的`设备实例` |
| 杆塔元件 | 杆塔或线路设施节点中的`部件实例` |
| 运行环境 | `环境标注` |
| 缺陷隐患 | 缺陷载体节点内部的`缺陷实例` |

`知识层任务状态`只保存完成状态和对象编号引用，不重复保存标签值。

## 7. 阶段三：缺陷标注

### 7.1 先生成待检查载体队列

阶段二结束后，从对象树生成待检查载体队列。设施、设备、部件和子部件只要适用于当前拍摄任务，都可以成为缺陷载体。

每个载体必须得到以下检查结论之一：

```text
已完成有缺陷
已完成未发现明显异常
载体或检查部位本图不可见
图像证据不足无法判定
待人工复核
不适用于当前任务
未处理
```

`未处理`禁止进入训练。`NO_VISIBLE_ANOMALY`是检查结论兼容代码，新标注不应为了表达“正常”而创建缺陷实例。

### 7.2 缺陷候选生成

```text
当前载体精确候选或对象载体候选
∩ 当前业务域和设施场景
∩ 当前设备、部件或子部件路径
∩ 当前静态属性约束
∩ 当前图像模态和拍摄任务
∩ 当前启用版本
= 本轮缺陷候选
```

候选优先级为：

```text
子部件精确映射
→ 部件精确映射
→ 载体代码族受限映射
→ 对象载体映射
→ 受限通用候选
→ OTHER_REVIEW
```

找不到精确映射时不得直接开放全部缺陷代码。

例如识别到“主变压器—散热器—连接管接头”后，可以开放油污痕迹、渗漏油、腐蚀、松动和破损等候选；不能开放导线断股、杆塔倾斜和绝缘子伞裙破损。

### 7.3 材质与载体约束

“杆塔”是上位概念，不能笼统规定“杆塔不会生锈”。必须联合杆塔材质和缺陷载体：

- 水泥杆或复合材料杆的杆体：不允许金属腐蚀标签；
- 钢管杆杆体和角钢塔塔材：允许腐蚀候选；
- 水泥杆上的金属抱箍、横担、法兰和紧固件：仍允许相应锈蚀标签。

因此：

```text
水泥杆 → 杆体 → 腐蚀：阻断
水泥杆 → 抱箍 → 抱箍锈蚀：允许
角钢塔 → 塔身 → 腐蚀：允许
```

### 7.4 绝缘子专项与文件名边界

绝缘子按以下路径渐进披露：

```text
设施
→ 绝缘子串或绝缘子类型
→ 绝缘子本体、瓷本体、玻璃本体或复合本体
→ 釉表面、伞裙或端部金具
→ 当前载体允许的缺陷候选
```

所有已定义的`jyz-*`绝缘子类型都必须使用绝缘子专用缺陷候选；即使新增型号暂时没有精确映射，也只能回退到绝缘子受限候选，不得沿父对象回退到杆塔裂纹、杆塔倾斜、抱箍锈蚀等结构缺陷。

可见现象的使用边界为：

- `INSULATOR_DISCHARGE_MARK`：局部放电样变色、焦斑或痕迹，但形态不足以确认具体放电过程；
- `INSULATOR_GLAZE_BURN_MARK`：瓷绝缘子釉表面可见灼伤、熔蚀或异常变色；
- `INSULATOR_ARC_BURN_MARK`：存在明显高温烧蚀、点蚀、熔蚀或炭化；
- `INSULATOR_FLASHOVER_TRACE`：存在沿爬电路径连续分布、跨伞裙或桥接式放电路径；
- `INSULATOR_TRACKING_EROSION`：存在沿面电痕、沟槽状电蚀或材料侵蚀；
- `INSULATOR_POLLUTION`：绝缘表面存在可见污秽附着。

文件名中的“雷击”属于外部故障原因，不是纯视觉标签；“一般/严重”属于外部业务等级。二者必须保存来源和图像可验证状态，不能直接写成视觉缺陷或视觉严重等级。图像不支持更具体结论时，优先使用放电样痕迹、不可判定或待人工复核，而不是使用`OTHER_REVIEW`代替不确定性。

### 7.5 缺陷必填关系

每个缺陷必须包含：

- 固定候选中的缺陷代码和中文名称；
- 所在载体对象编号；
- 候选树路径和候选披露轨迹编号；
- 视觉判定状态；
- 至少一条直接可见证据引用；
- 置信度或复核要求；
- 缺陷框，或无法画框的原因；
- 图像不能确认的内容。

文件名中的“雷击、渗漏油、一般、严重”等只能作为外部先验。若图像只显示焦斑或油污，应优先标注可见现象，将故障原因、持续状态或业务等级列为不确定信息或待人工复核。

## 8. 阶段四：两阶段自动校验

阶段四依次执行：

```text
阶段四A：确定性规则校验
→ 无阻断问题
→ 阶段四B：大模型语义复核
→ 最终门禁
```

规则引擎负责可以稳定计算的问题；大模型负责需要理解图像和语义的问题。大模型不得绕过台账、阶段门禁和候选披露轨迹。

### 8.1 阶段四A：确定性规则校验

按以下顺序执行：

1. JSON结构校验：必填字段、数据类型、枚举、坐标和置信度范围；
2. 标签台账校验：代码存在、名称匹配、版本启用、标签性质正确；
3. 渐进披露轨迹校验：最终选择属于当时披露的候选；
4. 候选树路径校验：业务域、场景、设施、设备、部件和子部件路径合法；
5. 对象树关系校验：嵌套关系正确、编号全树唯一、主要对象引用存在；
6. 载体缺陷兼容校验：缺陷属于当前载体允许候选；
7. 静态属性约束校验：材质、任务、模态等跨字段规则成立；
8. 来源和证据形式校验：视觉证据引用存在，外部信息来源明确；
9. 任务完整性校验：所有适用阶段、知识层和载体没有未处理状态。

确定性规则发现阻断问题时，直接退回对应阶段，不调用大模型。安全的格式归一化可以自动处理；标签替换、载体移动和证据补写等语义修改不得静默自动执行。

### 8.2 规则问题结构

规则结果不能只有“通过/失败”，每个问题必须记录：

```json
{
  "规则编号": "MAT-CONCRETE-BODY-001",
  "校验类别": "静态属性约束校验",
  "问题级别": "阻断",
  "问题位置": "标注对象树/设施01/部件实例/杆体01/缺陷实例/缺陷01",
  "实际内容": {"杆塔材质": "水泥杆", "缺陷代码": "CORROSION"},
  "期望要求": "水泥杆杆体不能使用金属腐蚀标签",
  "处理建议": "删除腐蚀标签，或确认载体是否实际为金属抱箍、横担、法兰或紧固件",
  "退回阶段": "DEFECT"
}
```

问题级别固定为`阻断、警告、提示、不适用`。

### 8.3 阶段四B：大模型语义复核

规则校验无阻断后，大模型结合原始图像、阶段一至三标注结果和相关候选子树审核：

- 图像路由是否符合视觉场景；
- 主要对象是否真的是画面主体；
- 设备、部件和子部件识别是否符合可见结构；
- 是否虚构不可见父对象或遗漏明显对象；
- 缺陷标签是否受到直接可见证据支持；
- 缺陷是否绑定到正确载体；
- 是否把油污、焦斑等现象过度解释为渗漏、雷击等原因；
- 文件名、台账和工单是否与视觉结论正确隔离；
- 是否遗漏明显异常；
- 派生描述是否与结构化事实一致。

审核模型只能在已激活标签包和当前候选子树内提出正式标签修改建议；候选外对象只能建议`OTHER_REVIEW`和标签扩展审核。

### 8.4 视觉优先复核

为了降低文件名诱导，大模型语义复核采用两个视图：

1. 视觉复核视图：输入原始图像、结构化标注和相关候选子树，暂不提供文件名中的缺陷原因和严重等级；
2. 多模态一致性视图：再加入文件名、台账和工单，检查来源隔离和冲突处理。

两个视图都属于阶段四B，不增加新的业务阶段。

### 8.5 大模型问题结构

大模型不能只输出自然语言审核意见，必须输出结构化问题：

```json
{
  "问题编号": "LLM-REVIEW-001",
  "问题级别": "阻断",
  "对象编号": "部件01",
  "问题类型": "缺陷结论强于视觉证据",
  "原标注": "渗漏油",
  "图像可支持结论": "连接处存在褐色油污状痕迹",
  "建议标签": "油污痕迹",
  "不可确认内容": ["无法确认是否仍在持续渗漏"],
  "退回阶段": "DEFECT",
  "是否要求人工复核": true
}
```

审核模型应使用独立审核提示词和独立上下文，不继承标注模型的自由推理说明；保存模型标识、提示词版本、图像摘要和标注摘要，确保审核可复现。

## 9. 最终门禁与回退

| 规则校验 | 大模型语义复核 | 最终处理 |
|---|---|---|
| 存在阻断 | 不执行 | 退回对应阶段 |
| 通过或仅警告 | 通过 | 允许生成派生输出 |
| 通过 | 需要修改 | 退回对应阶段并重新校验 |
| 通过 | 无法判定 | 转人工复核 |
| 通过 | 候选外对象 | 转标签扩展审核 |
| 与规则结论冲突 | 任意 | 转人工复核 |

大模型提出修改建议后，必须回到对应阶段修改权威结构化标注，再重新执行规则校验和语义复核；不能把审核模型的建议直接视为最终事实。

以下情况必须人工复核：

- 路由无法稳定确定；
- 候选树中没有合适的设施、设备、部件或缺陷；
- 图像与文件名、台账或工单明显冲突；
- 规则引擎与大模型审核结论冲突；
- 单幅图像不足以确认故障原因或严重等级；
- 关键缺陷证据不足但业务风险较高。

## 10. 单图校验、批次校验与人工一致性

单图阶段执行结构、台账、关系、证据、完整性和跨字段规则。数据泄漏与近重复图像属于批次校验，应在数据集导出时按线路、杆塔、设备和巡检事件分组执行，不能在单张JSON中伪装成已经通过。

配电架空标注框质检可参考文档使用IoU不低于0.85；多人抽检一致性目标为Krippendorff α大于0.8。阈值是数据集质量目标，不代替逐项视觉审核。

## 11. JSON转描述文本

只有最终门禁允许进入`DERIVE`后，才能从审核通过的结构化字段派生：

- 主体描述：主要设施、设备或部件；
- 属性描述：拍摄范围、部件、位置、材质和状态；
- 纯视觉完整描述：只使用图像证据；
- 业务完整描述：可加入文件名、台账或工单信息，但必须注明来源；
- 简短检索描述：设备＋部件＋可见异常；
- 组合检索修改文本：保持项＋变化项＋目标状态＋排除项。

禁止把不确定信息写成肯定结论，禁止直接用文件名覆盖视觉结果。任何结构化标注修改都会使既有派生文本失效，必须重新生成。

## 12. 版本、扩展与审计

- 标签代码进入模型训练后原则上不修改；
- 中文展示名可以通过版本映射调整；
- 新标签先进入候选申请，经专家审核后在新版本启用；
- 发电、输电、变电、配电和用电分别维护领域标签包；
- 总台账是唯一人工维护事实源，Skill中的标签资源应由总台账同步生成，不能双份手改；
- 标签包、规则集、审核提示词和派生模板分别记录版本；
- PDF中的“188类”和各层标题合计“194类”存在口径差异，正式导入前应按实标签、启用状态和参与训练状态重新核数。

候选覆盖和严格使用边界见`候选标签覆盖审计2.0.md`。修改候选树或模板后必须执行：

```bash
python3 校验候选树.py
```

数据库、目标检测训练或统计需要扁平表时，应从`标注对象树`生成派生设备表、部件表和缺陷表；派生结果不是第二份人工标注，不得反向形成两个事实源。

## 13. power-image-annotation Skill接口

Skill按阶段读取资源，不一次性把全量候选发送给视觉模型：

```text
power-image-annotation/
├── SKILL.md
├── agents/openai.yaml
├── references/
│   ├── 标注规则2.0.md
│   ├── 标签候选树2.0.json
│   ├── 候选标签覆盖审计2.0.md
│   ├── 大模型语义复核规范.md
│   └── 资源清单.json
├── assets/
│   └── 标注规则2.0.json
└── scripts/
    ├── select_candidates.py
    ├── validate_annotation.py
    ├── render_captions.py
    ├── sync_resources.py
    └── self_test.py
```

推荐调用顺序：

```text
select_candidates.py route
→ select_candidates.py scene
→ select_candidates.py subject
→ select_candidates.py parts
→ select_candidates.py defects
→ validate_annotation.py
→ 大模型语义复核
→ render_captions.py
```

其中`subject`和`parts`都属于阶段二，`defects`属于阶段三。脚本返回的是当前候选视图；最终对象层级和四阶段标注规则保持不变。

项目台账修改并通过`校验候选树.py`后，必须运行Skill中的`sync_resources.py`更新只读运行时快照，再运行`self_test.py`验证变压器部件、杆塔材质约束、候选轨迹和严格规则校验没有发生退化。
